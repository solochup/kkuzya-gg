# KKUZYA.GG — сайт аналитики (версия 0.3.0)

## Запуск сайта на Windows

Двойной щелчок по `run-site.bat`. При первом запуске он сам установит зависимости сайта и соберёт его, потом откроет http://127.0.0.1:4173/ .
Пока окно открыто, сервер каждые 5 минут проверяет новые матчи kkuzya в Deadlock API.

То же из командной строки (в корне проекта):

| команда | что делает |
|---|---|
| `npm --prefix web install` | один раз: зависимости сайта (корень проекта зависимостей не имеет) |
| `npm run build` | собрать сайт в `web/dist` |
| `npm start` | сайт + синхронизация каждые 5 мин (порт 4173, переменная `PORT`) |
| `npm run start:offline` | сайт на сохранённых данных, без обращения к API |
| `npm run sync` | один проход синхронизации (для расписания) |
| `npm run dev` | режим разработки Vite (данные берутся из `data/public`) |
| `npm test` | тесты ядра и сервера (с `FIXTURE=путь\metadata.json` — и на реальном матче) |
| `npm run test:web` | unit-тесты фронтенда |
| `npm run smoke` | проверка в настоящем Chrome/Edge: страницы, вкладки, консоль, скриншоты |
| `npm run bench -- <metadata.json>` | замер времени обработки одного матча |

Нужен Node.js 20.19 или новее (проверочный инструмент `check.mjs` по-прежнему работает на Node 18).

### Как устроено

```
Deadlock API ──► server/sync.js ──► data/cache   (история с ETag, сводки матчей навсегда, справочники на 1 ч)
                     │          └─► data/public  (profile-5.json, profile-10.json, matches/<id>.json, status.json)
                     └ lib/ (проверенное ядро: digest, metrics, items + profile, assets-slim, modes)
web/ (React + ECharts) ──► читает только data/public; status.json раз в минуту
```

- Метаданные матча (1–1,5 МБ) обрабатываются только на сервере; в браузер уходит профиль на 50–70 КБ.
- Матчи Street Brawl (`game_mode 4`) не смешиваются с обычными 6×6; незавершённые матчи пропускаются.
- Если метаданных нового матча ещё нет, матч ждёт повтора (2, 4, 8 … 60 мин), через 12 ч помечается недоступным.
- Ошибки 429/5xx не ломают сайт: показывается последний кеш, индикатор вверху сообщает возраст данных и причину.
- Позиции: карта перемещений и близость к игрокам — только для матчей, где путь сошёлся со смертями.
  Места убийств и смертей берутся из `death_details` и от путей не зависят.
- Папка `data/` создаётся синхронизацией; удалять её безопасно — данные скачаются заново.
- Публикация на Cloudflare (бесплатная схема) описана в `deploy/CLOUDFLARE.md`; пока ничего не опубликовано.

# Проверка Deadlock API (версия 0.2.0): как запустить на Windows

Инструмент сам запрашивает историю матчей игрока 1600662883, берёт последние 10 матчей, скачивает справочники, считает предварительные показатели и пишет короткий отчёт. Вручную ничего скачивать не нужно.

## Первый запуск (проверка)

1. **Node.js** уже установлен, если прошлый запуск работал. Иначе: https://nodejs.org , кнопка **LTS**.
2. Распакуй архив (правая кнопка, «Извлечь всё») **в новую папку**, не поверх старой.
3. Двойной щелчок по `run-check.bat`. Займёт 1–3 минуты.
4. Открой `out\report.md` в Блокноте, выдели всё (Ctrl+A), скопируй (Ctrl+C) и пришли в чат. Дополнительно можешь прислать `out\paths-diagnostics.json` (около 15 КБ).

## Справочники героев и предметов

Справочники берутся из основного API:

- герои: `https://api.deadlock-api.com/v1/assets/heroes` (около 2 МБ)
- предметы: `https://api.deadlock-api.com/v1/assets/items` (около 6,5 МБ)

Старый адрес `assets.deadlock-api.com` больше не существует (DNS: имя не найдено), он не используется.

Как отличаются предметы в справочнике (поле `type`):

| `type` | что это |
|---|---|
| `upgrade` | предмет из магазина (есть слот weapon/spirit/vitality, уровень 1–5, цена) |
| `ability` | способность героя; в матче такая запись означает вложенное очко способности |
| `weapon` | служебная запись оружия, в матчах не встречается |

Предмет с `shopable: false` или `disabled: true` всё равно считается покупкой: его просто убрали из магазина, но в старых матчах он есть. Если ID нет в справочнике, используется запасное правило «`upgrade_id = 1` это покупка» (на 326 записях из 10 реальных матчей оно совпало со справочником полностью).

## Если справочники не загрузились

В отчёте появятся строки «DNS …» и причина в скобках, например `(ENOTFOUND)` или `(CERT_...)`. Пришли их мне. Пока можно обойти так:

1. Открой в обычном браузере `https://api.deadlock-api.com/v1/assets/heroes`. Если страница открылась, нажми Ctrl+S и сохрани как `heroes.json` в папку инструмента.
2. То же для `https://api.deadlock-api.com/v1/assets/items`, сохрани как `items.json`.
3. Запусти в командной строке (в адресной строке Проводника этой папки напиши `cmd` и Enter):
   `node check.mjs --heroes-file heroes.json --items-file items.json`

Если страницы не открываются и в браузере, напиши мне: тогда нужен другой источник названий.

## Измерение задержки появления матча (новое)

Нужно, чтобы узнать, через сколько минут после конца игры матч появляется в API.

1. **Пока играешь или сразу после начала матча** запусти `run-watch.bat`. Окно должно оставаться открытым.
2. Инструмент раз в 3 минуты проверяет историю (дёшево, использует ETag) и сам заметит новый матч. Остановится, когда появятся метаданные нового матча.
3. Пришли `out\watch.md`.

Точность измерения около ±5 минут, потому что сервер кеширует историю до 5 минут.

## Если что-то пошло не так

- **«Node.js не найден»**: установи Node.js, закрой и открой окно заново.
- **Ошибки запросов (404, 403, 429, таймаут)**: это тоже результат. Всё равно пришли `out\report.md`.
- **Много ответов 429**: `node check.mjs --delay 1500`.
- **Windows блокирует запуск**: «Подробнее», затем «Выполнить в любом случае». Файлы `.bat` текстовые и безопасны для чтения в Блокноте.

## Параметры (по желанию)

| команда | что делает |
|---|---|
| `node check.mjs --matches 5` | разобрать 5 матчей |
| `node check.mjs --delay 1000` | пауза 1 секунда между запросами |
| `node check.mjs --heroes-file heroes.json --items-file items.json` | справочники из файлов |
| `node check.mjs --assets <адрес>` | другой адрес справочников (к нему добавляются `/heroes` и `/items`) |
| `node check.mjs --help` | все параметры |
| `node watch.mjs --interval 240 --hours 3` | наблюдение с другим шагом и сроком |

## Что нового в 0.2.0

- Причина сетевой ошибки показывается (раньше было только «fetch failed»), плюс проверка DNS.
- Время позиций приводится к игровому по смертям (на реальных данных это поднимает совпадение со смертями с 51% до 88%). Если путь игрока не сходится, позиции в матче не используются, и в отчёте указано почему.
- Сверка истории матчей с метаданными (герой, KDA, длительность, победа).
- Режим наблюдения за новым матчем (`watch.mjs`).
- Расписание снимков сравнивается без последнего снимка (он равен концу матча), поэтому ложных предупреждений больше нет.
- Справочники перенесены на `https://api.deadlock-api.com/v1/assets/…`. В индексе предметов появились картинки магазина (`shop_image`), признаки «есть в магазине», «активный предмет», тип способности (обычная/ульта) и герой способности.

## Что НЕ проверено

Задержка появления матча, лимиты запросов, работа CORS в настоящем браузере (сервер справочников отвечает `access-control-allow-origin: *`, но в браузере это не проверялось), смысл `combat_type`/`move_type`. Справочники проверены 2026-11-23 вручную и на 10 матчах, но `check.mjs` с новыми адресами в сети ещё не запускался. Показатели Aggression, Farming, Teamplay, Survivability и Damage предварительные, это не официальные рейтинги.

## Что внутри

```
check.mjs          основной запуск проверки
watch.mjs          наблюдение за новым матчем
run-check.bat      запуск проверки двойным щелчком
run-watch.bat      запуск наблюдения двойным щелчком
run-site.bat       запуск сайта KKUZYA.GG двойным щелчком
lib/               код расчётов, без привязки к Windows (пригоден для сервера)
server/            синхронизация с API, файловый кеш, локальный сервер сайта
web/               сайт (Vite + React + TypeScript + ECharts)
tools/             замер производительности, подготовка к Cloudflare Pages
deploy/            инструкция и шаблон публикации (не активированы)
tests/             автоматические тесты (run-tests.mjs — проверка, site-tests.mjs — сайт)
out/               сюда пишется отчёт проверки
data/              кеш и данные сайта (создаётся синхронизацией)
```
