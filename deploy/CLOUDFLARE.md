# Публикация KKUZYA.GG на Cloudflare (бесплатно)

> Ничего из этого ещё не выполнено. Публикация, создание проекта в Cloudflare и любые токены — только после согласования.

## Почему не Cloudflare Workers для обработки

Замер (`npm run bench -- <metadata.json>`): JSON.parse + buildDigest одного матча — медиана 5,3 мс, максимум 7,9 мс
на прогретом Node 26 (Windows, настольный процессор). Бесплатный Workers даёт 10 мс CPU на вызов; холодный изолят
медленнее, а первичная загрузка 10 матчей — это 50+ мс. Платный план ($5/мес) не подключаем без разрешения.

## Выбранная схема (0 ₽)

```
GitHub Actions (≈ каждые 15 мин)                                   Cloudflare Pages Free
  sync-cli → build → prepare-pages → publish-gate ──(только при изменениях)──► https://kkuzya-gg.pages.dev
  кеш data/ в actions/cache                                          index.html, assets/*, data/*.json
```

- Тяжёлые метаданные обрабатываются в GitHub Actions (Node, без лимита CPU).
- Сайт — статика: `index.html`, `assets/*` (кеш навсегда, имена с хешем), `data/*.json` (`no-cache`).
- Браузер раз в минуту проверяет `data/status.json` и перезагружает профиль, только если изменился `dataVersion`.
- Маршруты SPA (`/lab`) Pages отдаёт как `index.html`: в пакете нет `404.html` («Pages assumes that you are deploying a single-page application»).
- Заголовки — `web/public/_headers`.

## Когда сайт публикуется (`tools/publish-gate.mjs`, логика — `lib/publish.js`)

Отпечаток пакета `dist-pages` = SHA-256 всех файлов сайта, профилей (без `generatedAt`), подробностей матчей и
**видимого состояния** (`ok` / `stale` + виды ошибок). Время синхронизации, ETag, `steps`, `apiRequests`,
`dataVersion`, список ожидающих матчей в отпечаток не входят.

| Ситуация | Публикация |
|---|---|
| Новый матч, изменился профиль, новая версия кода сайта | да |
| Ничего не изменилось | нет |
| API недоступен 1 проход | нет (случайный сбой) |
| API недоступен 2 прохода подряд | да — посетитель видит «API недоступен · данные от …» |
| API снова работает | да |
| Сутки без публикаций | одна контрольная, чтобы возраст данных на сайте был честным |
| Достигнут лимит (20/сутки или 300/месяц, UTC) | нет, до следующих суток/месяца |
| Нет секрета `CLOUDFLARE_API_TOKEN` | нет, лимит не тратится |

- Опубликованный `status.json` содержит `publish: { mode: 'on-change', publishedAt, checkEveryMin, heartbeatHours }`.
  По нему сайт считает данные свежими до `heartbeatHours` + 2 ч и пишет в окне «Состояние данных», что сайт
  обновляется по изменениям. Если обновления остановились, через 26 ч сайт честно покажет «Данные давно не обновлялись».
- Попытка публикации засчитывается в лимит сразу; отпечаток фиксируется (`commit`) только после успешной загрузки —
  неудачная публикация повторится в следующем проходе.
- Журнал публикаций — `data/cache/publish-ledger.json` (в кеше Actions). Его копия без секретов публикуется как
  `data/publish.json`; при потере кеша журнал и счётчики восстанавливаются оттуда.
- Лимиты меняются переменными репозитория `KK_DEPLOY_MAX_DAY` / `KK_DEPLOY_MAX_MONTH`, но не выше 100 / 450.

## Лимиты Cloudflare Pages Free (официальная документация, страница limits от 19.11.2026)

- 500 сборок в месяц, 1 сборка одновременно, 20 000 файлов на сайт, 25 МиБ на файл, 100 проектов, 100 доменов на проект.
- `_headers` — до 100 правил; `_redirects` — до 2 000 статических + 100 динамических.
- Хранение деплоев: 30 дней, всегда сохраняются 100 последних + текущий продакшн. Ограничения на число деплоев не указано.
- **Не указано в документации:** засчитываются ли загрузки через `wrangler pages deploy` (Direct Upload) в 500 сборок,
  и что происходит при исчерпании лимита. Автоматического перехода на платный тариф документация не описывает;
  наш лимит 300/мес останавливает публикации раньше в любом случае.
- Запросы к статике бесплатны и не ограничены («requests to static assets are free and unlimited»).

## Что нужно для включения

1. Репозиторий на GitHub (публичный — без ограничения минут Actions).
2. Проект Cloudflare Pages `kkuzya-gg` (Direct Upload, production-ветка `main`) и API-токен с правом *Cloudflare Pages: Edit*.
3. Секреты репозитория `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`.
4. Переменная репозитория `KK_SITE_URL`, если адрес не `https://kkuzya-gg.pages.dev`.
5. Скопировать `deploy/github-workflow.yml.example` → `.github/workflows/kkuzya-sync.yml`,
   по желанию `deploy/github-ci.yml.example` → `.github/workflows/kkuzya-ci.yml`.
6. Свой домен `kkuzya.gg` — по желанию, в настройках Pages (покупка домена платная).

## Ручная публикация (одна команда, после согласования)

```
npm run sync && npm run build && npm run pages:prepare && node tools/publish-gate.mjs decide
npx wrangler@4.158.0 pages deploy dist-pages --project-name kkuzya-gg
node tools/publish-gate.mjs commit
```

## Ограничения бесплатной схемы

- Расписание GitHub Actions не точное: при нагрузке запуск задерживается, а иногда пропускается.
- В публичном репозитории GitHub отключает расписание после 60 дней без активности. Workflow не коммитит и не
  получает `actions: write`, поэтому продлевать нужно вручную: любой коммит раз в 1–2 месяца. С 45-го дня
  `publish-gate` пишет предупреждение в журнал запуска.
- Новый матч появляется на сайте с задержкой: время публикации в API (не измерено, см. `watch.mjs`) + до 15 минут
  расписания (плюс задержки GitHub) + до 5 минут кеша истории в API.
- Картинки героев, предметов, карты и аватар Steam загружаются напрямую с `assets-bucket.deadlock-api.com` и `avatars.steamstatic.com`.
